ACCESSIBILITY

Accessible learning — what is supported

Core game controls are keyboard operable. Number entry uses labeled controls. Ordered activities use selectable buttons and undo instead of requiring drag-and-drop. Feedback and some game state changes are announced using live regions. The interface respects reduced-motion and higher-contrast user preferences.

Language can be switched between English and Hindi in the interactive prototype. Some specialized words and translations still need human review; the app should not be treated as an authoritative Hindi assessment. The interface uses Unicode symbols and text descriptions; not every puzzle has yet received a full independent screen-reader audit.

Known gaps

Real-device tests on low-end Android phones, TalkBack, VoiceOver, NVDA, keyboard and zoom combinations remain pending. Classroom and disability-inclusive usability testing with appropriate permissions is also pending. This page does not claim WCAG certification.

Better alternatives

Students can skip unsuitable activities, practice a different age band, draw answers on paper, take a break or stop. If a puzzle is inaccessible, it must not be interpreted as lower ability.
