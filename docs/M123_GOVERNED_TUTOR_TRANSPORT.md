## Implementation and limits

`npm run tutor:transport-rehearsal` uses real Node HTTP over 127.0.0.1 to a freshly created fixed synthetic fixture service, not an external model. Each eligible request derives its entire payload from the existing exact non-educational test fixture after source/version/language checks; no arbitrary prompt, URL, provider key, personal identifier, caller source, approval or paid dependency. Internal service uses a fresh random bearer secret, exact loopback Host/path/method, bounded request body and exact payload equality. No redirect following, compression, retries or arbitrary destination. Strict canonical compact JSON response, 800 request bytes, 1,024 streamed response bytes, 250 excerpt bytes, 800ms request deadline, one concurrent request and at most 20 reserved attempts per in-memory instance. These are wire byte limits, not provider token counts or a daily production quota. No billing occurs. Source/version/language/hash and exact excerpt are checked against the fixed fixture; malformed/ambiguous/oversized/mismatched responses return no excerpt or citation. Internal listener closes after each attempt. Existing production registry remains empty and disabled contract unchanged.

GET/PUT `/v1/tutor-transport-rehearsal` is developer-bearer-only on existing loopback service; teacher/reviewer roles denied. It is excluded from static deployment and added to restricted-host negative probes. `/v1/chat` remains nonexistent. Activation boundary reports zero authorized external requests and zero INR budget, cannot accept caller overrides. No real provider adapter, credential workflow, token accounting, live generation or human identity authentication has been implemented. Actual production activation requires authenticated source/rights evidence, independent educator/legal/safeguarding/provider review, school authorization, approved budget and operator policy, and restricted hosting validation. Real provider protocol, data-retention agreement, rate limits, cost accounting, review and safety evaluation need separate implementation after those decisions. No approval may be inferred from fixture success.
