# M32 B2 — Controlled scope and evidence-change protocol (draft)

**2026-11-24. Engineering governance template only; no educational, privacy, legal, school or child-facing release approval.**

A change begins as a GitHub PR/issue referencing the relevant **FP-###** task. Specify the concrete deliverable, exact source/test files, bilingual/source-of-truth changes, license/attribution, privacy/child impact, offline byte and performance impact, safe rollback and expected learning result. Prohibit hidden new cloud accounts, open child chat, pupil identifiers or trackers. No confidence or grade claims without independently checked evidence.

Before code merge, validate the work item ID and dependencies, source/test proof, versioned draft review records (including content hashes for any changed question), Hindi/English source presence, numerical correctness, keyboard alternatives, simple screen-reader text, offline worker cache update, strict noindex/CSP, verified static ZIP allowlist, private-source exposure denial and deliberately failing public preflight. Automated tests validate code structure, **not** teacher signatures, actual translation quality, copyright grants or a child's learning outcome.

For content changes, regenerate the read-only review-packet with SHA-256 source fingerprints and treat the previous corresponding review as stale. Qualified subject and Hindi reviewers must independently approve each actual published edition/chapter item; the 3,292 draft record backlog must not be auto-approved. AI hints currently use **UNREVIEWED** source content and must not be publicly presented as reviewed/generated tutoring.

For physical-device testing, provide actual low-end Android, TalkBack/VoiceOver/NVDA, print, slow-network and shared-device results from identified authorized testers, including failures. For hosting, a permitted Hostinger operator must prove restricted HTTPS staging, 401/403 handling of sensitive source files, exact fetched-byte parity with the checkout, recovery/rollback and noindex. ZIP build alone is not deployment.

**Final go/no-go:** A real school and guardian-authorized pilot, independent educational outcomes, six child safeguarding/legal operational human gates and real educational/rights review must be documented by accountable humans. Do not infer this from CI, the unassigned role ledger or source/test traceability.

Any scope addition beyond the 100-item plan requires a new recorded change request; maintain [the owner-role ledger](B2_ROLE_LEDGER.json), [task register](MASTER_100_WORK_ITEMS.json), [B1 dashboard](B1_PROGRESS_DASHBOARD.md) and [release gates](../RELEASE_GATES.md). Roll back unreviewed/unsafe functionality without exposing student data or weakening the public gate.
